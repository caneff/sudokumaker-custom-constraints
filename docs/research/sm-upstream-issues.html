Silent wrong answers

10 issues

The app shows no error. A rule stops enforcing, a solution count is wrong, or a helper returns the wrong cells. These matter most because nobody notices.

SM-01correctness

A custom-type board has no rows or columns, and nothing says so

What happens
The solver adds its row and column houses only when the puzzle header's type is "sudoku" or absent. A "custom" board with a region constraint enforces boxes and givens only. The app still solves, times, and counts solutions on that looser puzzle.
Measured
A 9x9 with 44 givens that CP-SAT proves unique in 0.01 s timed out at 300 s. A 6x6 whose true count is 2 came back as 5 solutions. Adding rows and columns fixed both. It cost three tickets of quad-rank work.
Suggest
Warn in the editor when a custom-type board has regions but no row or column constraint, or make row/column houses an explicit toggle on custom boards.
Evidence
docs/gotchas.md §9 · docs/research/validate-only-probe.md · issues #324, #328, #335, #339
SM-02correctness

replaceComponent with a custom component does nothing

What happens
puzzle.replaceComponent(instance, new X(...)) works when X is a built-in such as SkyscraperComponent. When X is a custom component from a sibling code segment, the swap produces nothing and the rule never enforces. No error appears in the UI or the console.
Why it bites
The app's own edge-clue template uses exactly this shape: a watcher waits for the clue, then swaps itself out. Copying the template with a custom target kills the whole constraint.
Suggest
Support custom targets, or throw a visible error when the replacement is not a built-in.
Evidence
docs/gotchas.md §1 (verified live)
SM-03correctness

A custom validate that returns { valid: false } reads as satisfied

What happens
The custom-code wrapper tests the author's return value for truthiness: validateWrapper() ? __VALID : { valid: false, … }. An object is truthy. So the exact result shape the built-in components return is treated as a pass, every time.
Measured
Live probe, typing a digit the component forbids: a bare false turns the cells red; { valid: false, message } leaves them black. The same return also never rejects a state in the solver.
Suggest
Accept the object form (read .valid), or reject non-boolean returns with a console error.
Evidence
docs/research/ui-conflict-highlight.md (live probe table) · docs/gotchas.md §2
SM-04soundness

Component objects are shared by every search branch, and nothing warns authors

What happens
SolverState.clone() copies the component set by reference. Candidate state is cloned per branch and thrown away on backtrack; anything a component writes on instance survives. A cached flag computed from one branch's candidates then fires in a parent state where it is false, and the component removes a true candidate.
Measured
This repo shipped that bug twice: a latched instance.oneToN gate (#336, unsound) and a memo written after puzzle.stop() that stopped re-declaring a dead branch (#329).
Suggest
Document it in the custom-constraint help. Better: give components a per-state scratch slot that is cloned with the state.
Evidence
docs/component-contract.md · docs/research/bundle-api-reference.md (clone()) · issues #329, #336
SM-05soundness · latent

The fish step assumes every row house spans the whole board

What happens
The X-Wing / Fishes step walks every board row 0..height-1 and treats each Row-tagged house as covering the full row. On a board with an outer clue ring, those houses cover the interior only, so the step would push eliminations onto ring cells.
Why it is quiet today
The step set for type: "custom" puzzles leaves out XWings, Fishes and AlmostXWings. That gate is unrelated to the bug. Enabling fish for custom puzzles, or building a ringed board as type: "sudoku", makes it a live soundness break.
Suggest
Iterate the house's own cells instead of board rows, or check that the houses partition the rows before running the step.
Evidence
docs/research/394-fish-on-frame-boards.md (bundle read, step-type set qn)
SM-06correctnessunresolved

Four outside-sudoku boards read “not unique” in the app; CP-SAT proves them unique

What happens
Every shipped examples/outside-sudoku link (4x4, 6x6, 9x9, local) reports not-unique in the app, in 200–900 ms. The generator's CP-SAT model proves each unique. The disagreement predates the frame-reader change.
Status
Not yet attributed. It is either a missing constraint in the app or a mismatch in the generator's encoding. It is on this list because it reproduces in seconds and needs someone who can read the solver's solution output.
Evidence
docs/frame-link-verdicts.md “The nine” · issue #398 (open)
SM-07correctness

getCoordsPointedAtByOuterClue swaps the two bottom corners

What happens
The BottomRight ray starts at the bottom-left cell and the BottomLeft ray at the bottom-right. All four corner cases also run min(width, height) steps, which is not the visual diagonal on a non-square grid.
Measured
Run against the bundle on a 9x9: the bottom-right ray starts at (0,8), the bottom-left ray at (8,8).
Suggest
Swap the two start corners; walk the true diagonal of the board's shape.
Evidence
docs/research/bundle-api-reference.md “Bundle bugs” #1
SM-08correctness

SelfCounting solves with a different engine when verbose solving is on

What happens
SelfCountingComponent.initialize emits SelfCountingSumComponent when verboseSolvingEnabled is set and SelfCountingStateComponent otherwise. The two prune differently, so the same puzzle can step and time differently depending on a display setting.
Suggest
Use one engine and gate only the explanation text on the flag.
Evidence
docs/research/bundle-api-reference.md (SelfCounting section)
SM-09correctness

groupsArePolarityPair builds both masks from the low half

What happens
The high mask uses the same digit < midpoint test as the low mask. On digits 1–9, {1..4} with {5}, or with itself, passes as a low/high pair; {6..9} with anything but the low half fails.
Suggest
Flip the comparison for the high mask. Confirmed in the minified original, so it is not a deobfuscation artifact.
Evidence
docs/research/bundle-api-reference.md “Bundle bugs” #2 · bundle.claude.js:10382
SM-10correctness

Geometry helpers return a wrong in-range id instead of undefined

What happens
getCellsTouchingEdge uses the unchecked getIdFromCoords, so a border edge yields a bogus cell id. Other off-grid coordinate paths do the same. getCellAt already has a safe variant; these do not use it.
Suggest
Route every helper through getIdFromCoordsSafe and skip undefined.
Evidence
docs/research/bundle-api-reference.md (getCellsTouchingEdge, coordinate notes)

Solver strength & speed

5 issues

Answers are right, but the solver is weaker or slower than it needs to be. Puzzles time out, and AutoStep under-reports what logic can reach.

SM-11strength

Sudoku houses are below arc consistency inside trials

What happens
HouseComponent and DifferentDigitsComponent have no set-based update. Their Hall-set strength comes from the naked/hidden set logic steps, which run only at the top level. Inside ByContradictionLogicStep's hypotheses a house gives singles only.
Measured
A plain 9x9, 25 givens, no custom rule: AutoStep reaches 53/81. The same board with a matching-based all-different filter per house reaches 81/81, checked against CP-SAT.
Suggest
Give the house components a bitmask GAC update (a Régin filter on 9 cells is cheap), or run set steps inside trials.
Evidence
docs/gotchas.md §12 · docs/research/all-different-gac.md · docs/research/406-gac-demo/
SM-12strength

The native Skyscraper constraint deduces nothing while its clue is unsolved

What happens
SkyscraperComponent(name, amount, cells) reasons from a known amount only. With the clue cell blank it prunes nothing, so solver-filled outside clues get no help from the built-in.
Measured
Shipped Skyscrapers 9x9 (20 outside clues, 7 givens): this repo's two-sided component proves it unique in 8.3 s. The native type 503 constraint on the same board finds no first solution inside the app's 300 s limit, cold or after logic.
Suggest
Prune the clue cell's candidates from the line, and the line from the clue's candidate range.
Evidence
examples/skyscraper/README.md timing rows · docs/research/skyscraper-builtin-constraint-baseline.md · docs/builtin-components.md
SM-13speed

Cell ids from the geometry helpers slow the solver until coerced with | 0

What happens
Ids from getCellAt, getAllRows() and getAllColumns() look like plain numbers: typeof is "number" and they compare === to JSON ids. The solver still runs slower on them.
Measured
Eighteen HouseComponents built straight from getAllRows() ran 1.18× the cages they replaced; the same code with .map(c => c | 0) ran 0.97×. Candidate reads through getCellAt ids cost about 1.3×. Four interleaved rounds, cold.
Suggest
Coerce ids to small integers inside the helpers. While there: the two row/column helpers are one-shot generators that include the clue ring, which the docs do not say.
Evidence
docs/gotchas.md §10 · docs/puzzle-api.md · issues #276, #394
SM-14strength · speed

Built-in sum propagation is weaker than a standard killer-cage propagator

What happens
Compared with the closest public solver's sum handler: no required-digit reasoning; no cage/house complement; a multi-target cage relaxes to the whole [min, max] interval; repeat-allowed and weighted sums get bounds only. The bounds pass rescans every other cell per cell, O(n²) per cage, with a fresh Set each call. Whether a placed digit is excluded also depends on cellIds order.
Also
WeightedSumComponent accepts positive whole weights only, so a difference or negative coefficient needs a custom component.
Suggest
Precompute per-cage combination masks, then filter by required digits and allowed sums rather than the interval.
Evidence
docs/research/sm-vs-iss-sum.md · docs/research/iss-sum-handler.md
SM-15speed

“Which cells see each other” is an unindexed walk

What happens
getCellsCanHaveRepeats makes O(n) calls to getCellsSeenByCell, and each walks every component on that cell. Components that need peer information call it in update, which runs thousands of times per solve.
Suggest
Build a peer bitmask per cell once after registration and expose it read-only.
Evidence
docs/research/bundle-api-reference.md (getCellsCanHaveRepeats notes) · docs/gotchas.md §6

Authoring API

6 issues

Nothing breaks at runtime, but each of these sent an author the wrong way first. Most need a sentence of documentation or a thrown error.

SM-16api

A component cannot tell a hypothesis from the real board

What happens
AutoStep places digits hypothetically and propagates. Custom update runs inside those trials and gets no signal. Most of what it observes is a branch, and its last observation is a branch teardown.
Measured
A logging component on the Skyscrapers board recorded 55,537 snapshots; 25,832 held states impossible for the unique solution. A plain board with no custom rule shows the same (1,393 of 3,274). Reading them as board states produced four wrong diagnoses in a row.
Suggest
Document the call context. A puzzle.isHypothetical read would let diagnostics filter.
Evidence
docs/gotchas.md §11 · issue #406
SM-17api

Main code and components get two different helpers objects

What happens
Inside a component, helpers.lines and helpers.misc are undefined and helpers.geometry.getSubsetsPerRegion does not exist. The same names work in main code. The split was found only by reading the bundle.
Suggest
Expose the same read-only helpers in both, or document the split beside the helper list.
Evidence
docs/puzzle-api.md “Two helpers objects”
SM-18api

A thrown error in validate becomes “unable to satisfy <name>”

What happens
A throw inside a custom validate is caught, logged, and treated as false. The puzzle reports “This puzzle is broken: unable to satisfy …”, the same text as a real rule violation. A typo reads as a broken puzzle.
Suggest
Surface the exception text in the verdict, or label it as a code error.
Evidence
docs/component-contract.md · docs/research/validate-only-probe.md
SM-19api

Custom components cannot set a value; built-ins can

What happens
SolverPuzzleView has no way to yield a SetValue change. Built-ins such as SameGroupComponent.onValueSet yield one directly. A custom component must remove candidates down to one instead, which is more changes and more code.
Suggest
Add puzzle.setValueChange(value, cell) to the solver view.
Evidence
docs/research/bundle-api-reference.md (change types)
SM-20api

DigitSet set algebra mutates the receiver

What happens
a.intersect(b), union, subtract and xor change a and return it. The chaining shape reads as pure. getCandidates returns a DigitSet, so intersecting it in place is an easy mistake.
Suggest
Document it on the type, or add non-mutating variants.
Evidence
docs/puzzle-api.md · docs/gotchas.md §4
SM-21api

A local const silently hides an injected global

What happens
Code segments receive globals with generic names (SudokuDigitSet, MathUtils, ArrayUtils, SetUtils). A top-level const of the same name is legal and shadows the injected one with no warning.
Suggest
Namespace the injected utilities, or warn on shadowing at load time.
Evidence
docs/research/bundle-api-reference.md (code-segment wrapper)

Editor & sharing

4 issues

What a setter or solver sees on screen.

SM-22ux

No keyboard entry past 9, and the wide pad swallows keys

What happens
The app supports digits above 9 but has no hotkey for them; they need the on-screen pad. While the pad's second screen (10–12) shows, keys 1–9 do nothing at all. Found on a fillomino board with digits 1–12.
Suggest
Accept multi-key or modifier entry for 10+, and keep 1–9 hotkeys live on every pad screen.
Evidence
docs/real-app-timing.md · issues #293, #307
SM-23ux

A conflict paints the whole component red

What happens
The conflict highlight marks every cell in the component's cellIds. No cell list on a validate result is read, for built-ins either. One wrong digit on a long custom line turns the whole line red. A disabled or solver-ignored constraint also loses its highlight with no indication.
Suggest
Read an optional cells field from the validate result and highlight only those.
Evidence
docs/research/ui-conflict-highlight.md
SM-24ux

“Unique based on entered values” is easy to read as a proof

What happens
A uniqueness check run with digits already on the grid proves uniqueness of that partial position, not the puzzle. The verdict says “based on already entered values and pencil marks” in running text. This repo built tooling to catch the case.
Suggest
Show that verdict in a distinct style, with a one-click “check from givens only”.
Evidence
docs/real-app-timing.md
SM-25sharing

The whole puzzle lives in the URL, with no size warning

What happens
There is no server store; the link is lz-string JSON. Custom-constraint links here run around 10 KB. A large component can push a link past browser or chat length limits and truncate it, which loses the puzzle silently.
Suggest
Show the link length on share and warn above common limits; offer a stored short link.
Evidence
docs/gotchas.md §7–8 · AGENTS.md (link-size rule)
